# LoFiClaude V1.2 产品开发计划

## 目标
把 LoFiClaude 从“可用的本机氛围播放器”推进到“可长期使用的对话式专注房间”。核心循环保持：打开房间、选择氛围、专注、与 Clawd 对话、留下本地记录。

## P0：稳定核心循环

| 项目 | 用户价值 | 实现范围 | 验收标准 |
|---|---|---|---|
| 音乐来源状态 | 用户知道当前到底是谁在播放 | 统一音乐/雨声/provider 状态模型 | 任何切换都显示真实状态，不出现假成功 |
| 网易云对话播放 | 不需要学习 CLI | Bridge 白名单意图、歌单搜索、播放结果回传 | “切换到网易云，播放 lofi”可完成播放或给出明确错误 |
| 音频恢复 | 音频失败不需要刷新 | ncm-cli/本地雨声错误状态和重试 | 空队列、未登录、网络失败均可恢复或解释 |

## P1：提高连续使用价值

| 项目 | 用户价值 | 实现范围 | 验收标准 |
|---|---|---|---|
| 多歌单选择 | 用户不被固定第一结果限制 | 搜索结果摘要、编号选择、取消 | 用户可说“播放第二个”并播放对应歌单 |
| 最近播放 | 快速回到熟悉氛围 | 仅本机 LocalStorage 保存歌单 ID/名称 | 刷新后可恢复最近歌单，不保存凭证 |
| 播放队列摘要 | 理解下一首内容 | 展示当前歌单和当前曲目 | 下一首/上一首后标题和状态同步 |
| 专注回顾 | 形成复访反馈 | session 总结、今日/本周统计 | 结束 session 后 4 秒内生成本地总结 |

## P2：增强陪伴和内容深度

| 项目 | 用户价值 | 实现范围 | 验收标准 |
|---|---|---|---|
| 场景扩展 | 长期使用不单调 | 项目内原创场景，不新增运行时依赖 | 场景切换无溢出、无明显性能回退 |
| Clawd 行为 | 陪伴感更连贯 | 音乐切换、回复完成、久置行为反馈 | 状态变化与动作一致，不覆盖回复文本 |
| 语义场景 | 更少手动操作 | “雨天夜晚”“专注学习”等有限映射 | 语义映射可解释、不可用时不误切换 |

## 架构约束

- Claude CLI 继续使用 `--permission-mode dontAsk --tools ""`。
- Bridge 只接受固定 action 和严格参数，不执行任意 shell。
- AppID、PrivateKey、token、cookie 只留在本机配置。
- 不引入 p5.js、Three.js 或新的运行时依赖。
- 浏览器只消费状态事件，不直接调用 ncm-cli。

## 本轮实施顺序

1. 完成当前网易云意图的前端状态反馈和多结果协议。
2. 增加对应的 controller/server/bridgeClient 自动测试。
3. 更新 PRD、HANDOFF、TODO。
4. 运行 `npm test`、`npm run build`、`npm run verify:build`、`git diff --check`。
5. 创建本地 Git 提交和版本 tag。
